# Presenter notes - Leader session 5: MCP in your organization

**Audience:** C-level, managers, curious non-engineers. **Length:** 45 min. **Tone:** deciding - this is the session where MCP becomes a plan, not a briefing. No code, real decisions.

**One-line promise:** "You leave with a use-case scan you can run on any department and a one-slide business case you can present next week."

---

## Run of show (45 min)

| Time | Segment | What you do |
|------|---------|-------------|
| 0-3 | Welcome | Reframe the room off "should we adopt MCP?" onto "where does MCP-shaped work already exist here?" Read the ★ walk-out box aloud. |
| 3-18 | Part 1 · Find the wins | Teach the copy-paste tell. Open the five-question filter card live. Land the Daybreak stand-up example - it is the emotional anchor of the whole session. |
| 18-30 | Part 2 · Buy/build/become | Walk the three-posture SVG left to right. Spend the most energy on "expose" - hammer that it is a strategy decision, not IT. |
| 30-40 | Part 3 · ROI | Walk the before/after lead-time funnel. Open the one-slide business case card. This is the takeaway they will actually use. |
| 40-45 | Demos + close | Point them at Demo 1 (scan) and Demo 2 (one-slide case, model answer). Assign homework. |

## Never-cut beats (the session fails without these)

1. **The copy-paste tell** (Part 1). This is the reusable mental tool. If they leave with only one thing, it is "a manual hop is a server candidate."
2. **The Daybreak stand-up story.** It makes the tell concrete and shows the five-question filter passing in real life. Tell it as a story, not a bullet list.
3. **"Expose is a product decision, not IT"** (Part 2). This is the one insight that belongs at the exec table and nowhere else in the course. Say it twice.
4. **Integration lead-time as the board metric** (Part 3). Cost = small API project; benefit = every AI app gains it at once. This is what they present upward.

- Do NOT cut the Daybreak example or the expose-is-strategy beat to save time.

## Three likely questions + answers

**Q: "Isn't this just building APIs? We already have an integration team."**
A: Yes - and that is the point in their favor. A server is priced like a small API project, so the cost is familiar. What is new is that one server serves every AI app you run at once, and every future one for free. You are not buying an integration; you are buying a socket. That is the lead-time argument from Part 3.

**Q: "Should we expose our product as a server or is that giving away the store?"**
A: That is exactly the executive question, which is why it is not an IT decision. Framing: done first, you become the default node in your customers' AI stack; done late, a competitor does and you are the awkward custom integration. Answer it with product and GTM, not engineering. Homework question three is designed to start this conversation.

**Q: "How do we pick the first one when everyone wants their use case?"**
A: Do not pick the flashiest - pick the most repeated, lowest-blast-radius survivor of the five-question filter, with a clear owner. Read-only first. Winning one small, safe bet buys you the credibility to fund the next three. That is Demo 1's whole discipline.
